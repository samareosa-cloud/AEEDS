# HOG 기반 얼굴 검출기 (Template Matching) - Assignment #4

LectureNote 07 (Face-based Applications (1)) 실습. 
참조 얼굴 한 장(`face_ref.bmp`)의 HOG 특징과 대상 사진(`face_tar.bmp`)의 모든 36×36 영역을 비교해서, 학습 없이 얼굴 위치를 찾는다.

## 동작 방식

1. 현재 픽셀 위치에서 36×36 블록 B를 만든다.
2. B에서 HOG descriptor를 추출한다. (참조 영상과 같은 함수 사용)
3. 참조 HOG와 B의 HOG를 cosine similarity로 비교한다.
4. 모든 픽셀 위치(285 × 177 = 50,445곳)에서 반복한다.
5. 유사도로 Similarity Map(0~255)을 만들고, 임계값과 NMS를 통과한 곳에 36×36 박스를 그린다.

## HOG 구성

- Gradient: Prewitt 3×3
- 크기: `sqrt(sqrt(gx² + gy²))` (강한 엣지 영향 줄이기, 아래 회고 참고)
- 방향: 0~180°, 9-bin
- Block: 12×12, 6픽셀 간격 → 5×5 = 25개
- 정규화: block별 L2
- 차원: 25 × 9 = 225

## 코드 구조

```text
main
 ├─ face_ref.bmp, face_tar.bmp 읽기
 ├─ refHOG()        참조 얼굴 → 225차원 HOG
 └─ searchFaces()
      ├─ 모든 위치: 블록 B → computeHOG() → computeSimilarity()
      ├─ Similarity Map: 평균 이하 0, 최고점 255
      └─ 유사도 ≥ 0.872 + 주변 ±16에서 최대 → 36×36 박스
```

| 함수 | 역할 |
|---|---|
| `computeHOG` | 36×36 영상 → 225차원 HOG (참조/대상 공용) |
| `computeSimilarity` | 코사인 유사도 |
| `refHOG` | 참조 얼굴의 HOG |
| `searchFaces` | 슬라이딩, 유사도 맵, 임계값, NMS, 박스 |
| `drawBox` | 박스 그리기 |

## 회고: 고민했던 것들


### Similarity Map이 하얗게만 나왔다

코사인 유사도를 그대로 ×255 했더니 화면이 거의 하얬다. 처음엔 계산이 틀린 줄 알았다. 그런데 HOG 값은 전부 0 이상이고 block마다 정규화되니까, 얼굴이 아닌 배경도 유사도가 0.6~0.8로 높게 나오는 게 정상이었다. min-max, exp, 거듭제곱을 다 비교해 보고, 설명이 가장 단순한 "평균 이하는 0, 최고점은 255" 정규화로 정했다. 맵은 표시용이고, 판정은 원래 코사인 값으로 한다.

### 박스가 수십 개씩 겹쳤다

1픽셀씩 옮기니까 얼굴 하나 주변에 임계값을 넘는 위치가 수십 개 생겼다. 주변 ±16픽셀 안에서 가장 큰 점만 남기는 NMS를 넣어서 얼굴 하나에 박스 하나가 되게 했다. 임계값도 감으로 정하지 않고, NMS 후 후보들의 유사도를 출력해서 얼굴과 오검출 사이 값으로 골랐다.

### 끝까지 안 잡히던 한 명

가장 오래 붙잡고 있던 문제다. 고개를 기울이고 앞머리 때문에 그늘진 사람 얼굴은 유사도가 0.852로 10위였고, 티셔츠 무늬나 배경 같은 오검출 다섯 곳보다 낮았다. 그래서 임계값을 내리면 박스가 11개로 늘어나고, 올리면 그 얼굴이 빠졌다. **임계값 하나로는 답이 없는 상황**이었다.

L2 정규화와 12×12, 9-bin 조건은 바꾸고 싶지 않았다. 그래서 그 안에서 할 수 있는 걸 하나씩 실험했다.

| 시도 | 기울어진 얼굴 순위 | 결과 |
|---|---|---|
| 기본 | 10위 | 4명 |
| 입력 감마 보정 / 블러 | 4~10위 | 실패 |
| block·얼굴 중앙 가우시안 가중치 | 6~12위 | 실패 |
| 밝기 템플릿(NCC) 같이 쓰기 | 15위 이하 | 실패 |
| 여러 크기(0.9/1.0/1.1배) | 11위 | 실패 |
| 좌우 반전 참조, NMS 범위 변경 | 8~10위 | 실패 |
| **gradient 크기에 제곱근** | **5위** | **5명, 오검출 0** |

(참조 얼굴을 ±15° 돌려서 비교하는 방법도 5명이 잡혔지만, HOG 계산은 그대로 두고 싶어서 최종안에서는 뺐다.)

실패한 방법들을 보면서 원인을 다시 생각해 봤다. 히스토그램에 엣지 **세기**를 그대로 더하니까, 머리카락 경계나 옷 주름처럼 강한 엣지 몇 개가 히스토그램을 거의 다 차지하고 있었다. 엣지가 약한 그 얼굴은 눈·코·입 정보가 비교에 거의 안 들어갔던 것이다. 그래서 크기에 제곱근을 씌워 강한 엣지의 비중을 줄였더니, 그 얼굴이 0.878로 올라와 모든 오검출(최고 0.866)을 넘었다. 결국 바꾼 건 코드 한 줄이었다.

### 남은 한계

- 얼굴과 오검출의 차이가 0.012밖에 안 된다. 임계값을 0.868~0.876 밖으로 바꾸면 결과가 달라질 만큼 민감하다.
- 템플릿 매칭은 "얼굴인가"를 배우는 게 아니라 "엣지 분포가 비슷한가"만 본다. 그래서 원반, 나뭇잎, 옷 무늬도 점수가 높다.
- 정면 얼굴 한 장이 기준이라 회전, 크기 변화, 그림자에 약하다. 이 사진은 얼굴 크기가 비슷해서 넘어갔지만, 일반적인 경우엔 multi-scale이 필요하다.

이걸 직접 겪고 나니, 실제 검출기가 왜 Haar 특징 + AdaBoost(좋은 특징을 학습) + Cascade(배경을 빨리 버림)나 딥러닝을 쓰는지 와닿았다.
